FixAnything 논문 분석: 하나의 Video Model로 3DGS·NeRF·Mesh 렌더를 보정하는 법

3D rendering video와 clean-frame mask를 Wan2.1-I2V·LoRA·Flow-DPO로 처리하는 과정, DL3DV 데이터와 네 representation의 비교 결과를 분석합니다.

사진 몇 장으로 만든 3DGS에는 공중에 뜬 점이 생기고, NeRF는 안개처럼 흐려지며, mesh에는 구멍과 뒤틀린 texture가 남는다. FixAnything은 이 서로 다른 오류를 각각 고치지 않는다. 3D 표현을 camera path를 따라 영상으로 렌더링한 뒤, 하나의 Wan2.1 기반 video model이 자연스러운 영상으로 복원한다.

FixAnything: 3D-Consistent Rendering Refinement via Video Generative Priors는 3DGS·NeRF·mesh·sparse SfM point cloud를 같은 video-to-video 문제로 바꾼다. 이 글에서는 Input·Process·Output, clean anchor와 Flow-DPO의 역할, DL3DV-10K 학습 데이터, 3·6·9-view 비교 결과, 실행 비용과 공개 코드의 실제 범위를 나눠 살펴본다.

같은 날 공개된 연구를 요약한 AI CV SOTA 브리핑 — 2026년 8월 26일에서 이 논문만 분리해 확장한 분석이다.

1. 무엇을 고치고, 무엇은 고치지 않는가

입력 사진이 적으면 관측하지 못한 영역이 많아진다. 3DGS는 floater가 생기고, NeRF는 흐림과 foggy geometry를 만들며, mesh는 깊이가 불확실한 경계에서 구멍이나 texture distortion을 보인다. Sparse point cloud는 애초에 feature가 검출된 위치에만 점이 있어 벽과 하늘 같은 무늬 없는 영역이 비어 있다.

기존 후처리 연구는 대개 특정 표현에 맞춰 설계된다. FixAnything은 3D 내부 구조를 직접 읽지 않고, 모든 표현이 만들 수 있는 camera-path rendering video를 공통 인터페이스로 사용한다. 심하게 망가진 render에도 camera motion과 대략적인 scene layout은 남는다는 가정이다.

따라서 “3D reconstruction을 고친다”는 표현에는 경계가 있다. FixAnything이 직접 정제하는 대상은 novel-view 영상이다. 원래 Gaussian 위치·opacity, NeRF field, mesh vertex·texture, point coordinate를 업데이트하지 않는다. 복원 video로 다시 SfM이나 3D reconstruction을 수행할 수는 있지만, 그 downstream 단계는 논문의 기본 출력과 공개 inference CLI에 포함된 3D asset repair가 아니다.

2. Input — 모델에 무엇을 넣는가

Camera path를 따라 렌더링한 RGB video

첫 입력 x ∈ R^(T×3×H×W)는 3D representation을 원하는 camera trajectory로 렌더링한 RGB frame sequence다. 모델이 camera pose matrix나 Plücker ray를 별도 token으로 받지는 않는다. 움직이는 시점에서 나온 흐릿한 윤곽, 점의 이동, 가려짐 순서가 camera control 역할을 맡는다.

논문과 공개 모델의 기본 단위는 61 frame, 480×832 해상도다. 저장·CLI 표기로는 832×480이다. 61 frame보다 긴 영상은 겹치는 chunk로 나눈다. 프로젝트 페이지는 각 chunk 경계가 clean anchor를 공유하도록 구성한다고 설명하지만, 긴 전체 trajectory에서 chunk seam이 얼마나 누적되는지에 대한 정량 표는 없다.

Anchor를 표시하는 frame-level binary mask

두 번째 입력 m ∈ {0,1}^T는 frame마다 하나의 값을 갖는다. Training viewpoint에서 만든 깨끗한 frame에는 1, 복구할 novel-view frame에는 0을 준다. 이름은 mask지만 물체나 pixel 영역을 칠하는 inpainting mask가 아니다. 시간축의 frame label을 spatial dimension 전체로 broadcast해 latent channel에 붙인다.

Clean frame은 두 역할을 한다. 이미 맞는 내용을 다시 생성하지 않도록 신뢰 지점을 알려주고, 주변 degraded frame이 appearance·lighting·scene structure를 가져올 anchor가 된다. Anchor가 처음과 끝에만 있어야 하는 것은 아니다. 논문 Figure 1처럼 trajectory 중간에 섞여 있어도 된다.

공개 CLI는 --clean_frame_indices로 anchor를 지정하며 기본값은 첫 frame 0과 마지막 frame 60이다. 입력은 내부에서 마지막 frame을 네 번 반복해 65 frame으로 만든 뒤 출력 시 다시 61 frame으로 자른다. Wan VAE가 첫 frame은 독립적으로, 나머지는 시간축으로 압축하는 특성 때문에 마지막 anchor의 영향력을 보강하려는 구현이다.

3. Output — 정확히 무엇이 나오는가

출력 y ∈ R^(T×3×H×W)는 복원된 RGB video다. 목표는 scene content와 입력 camera motion을 유지하면서 floater, blur, fog, hole, scattered-point artifact를 자연스러운 frame으로 바꾸는 것이다.

  • 직접 출력: 복원 영상 generated.mp4, resize된 input.mp4, 입력·출력 비교 side_by_side.mp4
  • 출력하지 않음: 수정된 3DGS, NeRF checkpoint, triangle mesh, dense point cloud, metric depth, uncertainty map
  • 확률적 결과: Gaussian noise에서 시작하므로 seed가 달라지면 보이지 않던 영역의 완성도 달라진다.

공개 MapAnything 예제는 사진에서 reconstruction.glb와 rendered.mp4를 먼저 만든다. 여기서 GLB는 MapAnything 단계의 산출물이고, FixAnything 단계가 추가하는 것은 generated.mp4다. 영상이 좋아졌다고 GLB geometry까지 자동으로 고쳐진 것은 아니다.

4. Process — Wan2.1을 V2V 복원기로 바꾸는 일곱 단계

Step 1. 3D representation을 영상이라는 공통 형식으로 변환

3DGS·NeRF·mesh·sparse point cloud에서 동일한 camera trajectory를 따라 frame을 렌더링한다. Representation별 artifact 모양은 달라도 물체 윤곽과 camera 이동 방향은 어느 정도 보존된다. FixAnything은 이 render를 geometry scaffold로 삼는다.

Step 2. Frozen VAE가 degraded·clean video를 latent로 압축

기반 모델은 rectified flow로 학습된 Wan2.1-I2V-14B-480P다. Wan VAE encoder E가 degraded render x를 condition latent z_cond로, clean target y를 z_0로 바꾼다. Base model weight와 VAE는 동결한다.

Step 3. Noisy target·degraded condition·mask를 channel 방향으로 연결

학습 시 clean latent와 Gaussian noise를 시간 t에 따라 섞어 noisy latent z_t를 만든다. DiT 입력은 다음 세 항목을 channel 방향으로 이어 붙인 tensor다.

z_t = (1 - t) · z_0 + t · ε
DiT input = [z_t ; z_cond ; broadcast(mask)]

z_cond가 camera motion과 coarse layout을 전달하고 mask가 trust/fix 경계를 알려준다. 논문은 이 channel concatenation을 “minor architectural change”로 설명하지만, backbone block을 새로 설계하는 방식은 아니다. 공개 설명 기준으로는 기존 Wan2.1 DiT에 conditioning channel을 추가하고 LoRA만 학습한다.

Step 4. Rank-64 LoRA로 supervised flow matching

목표 velocity는 v = ε - z_0이며 모델이 예측한 velocity와의 제곱 오차로 학습한다. Rank 64 LoRA가 전체 parameter의 1% 미만을 갱신한다. 일반 video generation을 처음부터 배우는 것이 아니라 degraded render를 조건으로 clean video 방향을 찾는 방법만 적응시키는 단계다.

최종 SFT에는 DL3DV-10K에서 만든 500개 paired video가 쓰인다. 먼저 288×512에서 학습하고 480×832, 61 frame으로 올린다. SFT는 single H100에서 3,000 iteration 수행됐다.

Step 5. 같은 scene을 다섯 seed로 생성해 pose consistency를 측정

SFT 영상은 한 frame만 보면 그럴듯해도, 새로 만든 나무나 건물 모양이 시점마다 움직일 수 있다. 저자들은 별도 DL3DV scene 1,000개에서 scene마다 다섯 candidate를 서로 다른 random seed로 생성한다.

각 output에 SuperPoint feature와 LightGlue matching을 사용한 COLMAP SfM을 실행해 camera pose를 다시 구한다. 복원 pose를 known ground-truth pose와 비교하고 relative rotation accuracy와 relative translation accuracy의 AUC@5°를 계산한다. 영상의 feature가 여러 view에서 일관될수록 SfM이 원래 camera path를 잘 회수한다는 proxy다.

Step 6. AUC 차이가 큰 candidate로 Flow-DPO

다섯 candidate를 AUC@5°로 순위화하고 높은 sample을 winner, 낮은 sample을 loser로 묶는다. 두 점수 차이가 0.2 이상인 pair만 남긴다. SFT LoRA checkpoint를 reference model로 고정한 뒤 preferred·dispreferred sample의 velocity prediction 차이를 비교하는 Flow-DPO로 LoRA를 2,000 iteration 더 학습한다.

COLMAP은 학습용 preference를 만드는 데만 쓰인다. 추론 때 pose estimation을 매번 실행하는 구조가 아니다. Geometry 선호가 LoRA weight에 반영되므로 DPO 전후 inference graph와 denoising step 수는 같다.

Step 7. Noise에서 clean video까지 flow ODE를 적분

추론은 t=1의 Gaussian noise에서 출발해 학습한 velocity field를 t=0 방향으로 적분한다. Degraded video latent와 mask는 매 step condition으로 들어간다. 논문의 기본값은 50 denoising step이며 공개 CLI도 61-frame clip을 기본 입력으로 안내한다.

5. 학습 데이터 — 네 종류의 오류를 어떻게 만들었나

원본은 다양한 실제 장면 영상과 COLMAP reconstruction을 제공하는 DL3DV-10K다. Scene마다 training view 수 k를 3~12 사이에서 균일하게 뽑고, 그중 최소 두 view를 통과하는 61-frame camera trajectory를 만든다. 같은 trajectory를 네 3D 표현으로 렌더링해 degraded video를 얻고, 원본 frame sequence를 clean target으로 둔다.

네 representation은 별도 model을 학습하지 않고 한 LoRA의 SFT batch에서 함께 사용된다. “20개 video만으로 학습했다”는 설명은 data-efficiency ablation을 가리킨다. 논문에서 보고한 최종 model은 SFT paired video 500개와, preference candidate를 만드는 별도 DL3DV scene 1,000개×seed 5개를 사용한다. 20개는 final training volume이 아니다.

6. 평가 데이터와 지표

주 평가는 DL3DV-10K의 held-out scene 20개다. 각 scene에서 3·6·9개 frame을 training view로 균일하게 고르고, 그 view를 제외한 나머지 영상에서 8 frame 간격으로 query를 뽑는다. FixAnything의 네 입력 representation도 같은 sparse training view로 만든다.

AUC@5°는 유용하지만 완전한 3D 정확도 지표는 아니다. Camera pose가 잘 복원된다는 사실은 view 사이의 feature가 일관됨을 뜻할 뿐, surface depth·mesh topology·Gaussian geometry가 ground truth와 일치한다는 보장은 아니다. 논문은 Chamfer distance나 depth error로 출력 3D asset을 평가하지 않는다. 애초에 기본 출력도 video다.

7. DL3DV 비교 결과 — 3·6·9-view에서 무엇이 달라졌나

비교군은 sparse-view reconstruction과 3DGS rendering 후처리로 나뉜다. 표의 † 값은 3DGS-Enhancer와 Xu et al.에서 가져온 저자 보고값이고, 모든 방법을 FixAnything 코드베이스에서 같은 설정으로 재실행한 head-to-head 표는 아니다.

3-view 결과

같은 3DGS input끼리 보면 FixAnything PSNR 15.18은 강한 기존 후처리 Xu et al. 14.62보다 0.56 dB 높다. LPIPS 0.408도 3DGS-Enhancer 0.464보다 0.056 낮다. 다만 SSIM은 Xu et al. 0.471보다 0.019 낮다. 세 metric을 모두 같은 폭으로 이긴 결과는 아니다.

6-view 결과

사용자 브리핑에서 비교한 3DGS-Enhancer 대비 FixAnything 3DGS의 PSNR 차이는 16.94→17.65, +0.71 dB이고 LPIPS는 0.356→0.289로 0.067 낮다. 그러나 가장 높은 기존 PSNR은 Xu et al. 17.35이므로 최고 prior 대비 차이는 +0.30 dB다. SSIM은 Xu et al. 0.566보다 0.005 낮다.

같은 FixAnything weight에 mesh render를 넣으면 17.95 / 0.583 / 0.269로 네 입력 중 가장 좋고, sparse point도 17.74 / 0.568 / 0.271이다. 이는 point cloud만으로 3DGS를 완전히 대체할 수 있다는 제품 수준의 결론보다, clean anchor와 camera-motion scaffold가 충분하면 생성 prior가 많은 appearance를 채울 수 있다는 증거에 가깝다.

9-view 결과

9-view에서는 FixAnything 3DGS가 강한 prior보다 세 지표 모두 앞선다. PSNR은 Xu et al. 19.19보다 0.57 dB 높고, SSIM은 3DGS-Enhancer 0.630보다 0.002 높으며, LPIPS는 0.305에서 0.269로 0.036 낮다. 브리핑의 3DGS-Enhancer 대비 PSNR +1.26 dB도 맞지만, strongest-PSNR baseline과 비교하면 +0.57 dB다.

논문 supplementary와 프로젝트 페이지에는 MipNeRF-360·LLFF cross-dataset 결과도 제시된다. 본문은 3DGS input에서 기존 방법과 비슷한 PSNR·SSIM, 더 좋은 LPIPS라고 요약하지만 arXiv HTML 본문에는 숫자 표가 포함되지 않았다. 이 글의 headline 수치는 평가 protocol이 완전히 공개된 DL3DV main table로 제한한다.

8. Ablation — anchor와 Flow-DPO가 실제로 한 일

Flow-DPO는 pixel 점수보다 pose consistency를 크게 올렸다

PSNR·SSIM·LPIPS 변화는 작고 AUC@5°가 61.12→68.32로 크게 오른다. 저자 표현의 “7.2% improvement”는 표의 절대 차이 7.20 point다. Flow-DPO는 개별 frame을 더 선명하게 만드는 단계라기보다, seed에 따라 생기던 움직이는 hallucination을 줄여 SfM이 camera path를 회수하기 쉽게 만든다.

Mask가 없으면 이미 깨끗한 frame도 다시 그린다

Mask의 PSNR 효과는 논문 서술처럼 약 1.3 dB다. Model이 clean frame과 살짝 손상된 frame을 영상만 보고 구분하도록 맡기면, 원래 있던 표지판 같은 물체를 지우고 그 오류가 이웃 frame으로 퍼질 수 있다. Anchor는 content preservation의 핵심 입력이지 부가 옵션이 아니다.

20개 paired video는 가능성을 보인 최소 실험

20개만으로도 PSNR 16.70을 얻지만 final 500-video model보다 0.95 dB 낮다. 100→500에서는 +0.20 dB라 diminishing return도 보인다. 적은 paired data로 LoRA를 적응시킬 수 있다는 주장은 지지하지만, 최종 공개 weight가 20개만으로 만들어졌다고 쓰면 틀린다.

Denoising 5 step은 10배 빠르지만 LPIPS trade-off가 있다

Single H100에서 50→5 step은 309→31초로 약 9.97배 빠르다. 5 step의 PSNR·SSIM은 오히려 높지만 LPIPS는 0.289→0.313으로 나빠진다. 31초는 61 frame 생성 시간이지 camera stream을 즉시 처리하는 31 FPS가 아니다. Clip 전체를 받은 뒤 생성하는 offline 처리이며 real-time cleanup으로 부르기 어렵다.

9. Hallucination과 uncertainty

관측하지 않은 건물 뒷면을 “복구”할 때 유일한 정답을 알아낼 수는 없다. FixAnything은 video prior로 그럴듯한 내용을 만든다. 저자들은 기존 관측과 모순될 때를 실패하는 hallucination으로 구분하지만, 출력 하나만 보고 추론과 관측을 완전히 분리하는 내장 uncertainty head는 없다.

논문은 같은 입력을 seed 다섯 개로 반복 생성하고 pixel별 표준편차를 uncertainty proxy로 삼는다. DL3DV 6-view에서 confidence가 가장 높은 pixel 25%의 평균 PSNR은 25.7 dB, 가장 낮은 25%는 14.4 dB다. Error와 상관은 있지만, 다섯 번의 14B inference가 필요하고 calibration metric이나 failure threshold는 제공하지 않은 예비 분석이다.

10. 하드웨어와 실행 요구

약 60GB는 checkpoint download 용량 안내이지 최소 VRAM 수치가 아니다. 공식 README는 최소 GPU memory, CPU offload 성능, multi-GPU 설정을 따로 제시하지 않는다. 14B DiT와 VAE·T5·CLIP 계열 파일을 함께 준비해야 하므로 LoRA 파일이 작다고 전체 실행이 가벼운 것은 아니다.

M1 Pro MacBook은 공식 설치 경로가 아니다. 공개 환경은 CUDA·PyTorch 2.6과 선택적 FlashAttention-2를 전제로 하며 Apple Silicon용 MPS 검증, memory requirement, runtime이 보고되지 않았다. 개인 Mac에서 바로 돌릴 수 있다고 안내하기보다 NVIDIA CUDA 환경이나 cloud H100에서 먼저 재현하는 편이 현실적이다.

11. 이 논문의 장점

  • 표현 독립적인 interface가 단순하다. 3D 내부 parameter가 아니라 어느 renderer든 만들 수 있는 RGB video를 입력으로 쓴다.
  • 하나의 weight로 네 표현을 처리한다. NeRF·3DGS·mesh·sparse point별 전용 복원기를 따로 학습하지 않는다.
  • Camera control을 render 자체에서 얻는다. 별도 SE(3) conditioning architecture를 추가하지 않아 적은 paired data로 적응했다.
  • Anchor의 역할이 명확하다. 관측한 clean view를 보존하고 appearance가 이웃 frame으로 퍼질 기준을 제공한다.
  • Geometry consistency를 학습 신호로 쓴다. SfM pose recovery를 reward proxy로 바꿔 Flow-DPO에 넣고 추론 비용은 늘리지 않는다.
  • 공개 상태가 좋다. Inference code, 예제, LoRA weight, 자체 사진용 MapAnything pipeline과 Apache-2.0 license가 실제 공개됐다.

12. 한계와 결과 해석의 경계

  • 3D asset을 직접 고치지 않는다. 출력은 video이며 새로운 camera path가 필요하면 다시 render·inference해야 한다.
  • “Anything”은 검증된 네 표현 안에서 읽어야 한다. Dynamic scene, deformable object, outdoor city-scale path, 비RGB renderer를 포괄하는 실험은 아니다.
  • Anchor와 coarse geometry가 필요하다. Camera motion이나 scene layout이 render에 남지 않을 정도로 reconstruction이 무너지면 condition 자체가 잘못된다.
  • 보이지 않은 영역은 생성한다. 그럴듯한 영상과 실제 현장의 물리적 사실은 다를 수 있어 측량·검사·안전 판단의 ground truth로 쓰기 어렵다.
  • Pose AUC는 geometry accuracy의 proxy다. Metric depth, surface error, topology correctness를 직접 검증하지 않는다.
  • Long video는 chunk 처리다. 61 frame을 넘는 trajectory의 장기 identity·texture consistency와 seam 누적에 대한 정량 평가가 없다.
  • 최종 학습량은 20 pair보다 크다. 500 SFT pair 외에 1,000 scene의 다섯 candidate를 생성하고 COLMAP을 반복 실행한 Flow-DPO 준비 비용이 있다.
  • 비교표 일부는 prior paper 보고값이다. 모든 baseline이 동일 code·hardware·random seed로 재실행된 결과는 아니다.
  • 공개 문서는 inference 중심이다. SFT dataset 생성과 Flow-DPO 전체 training을 그대로 재현하는 end-to-end recipe는 README에 제공되지 않는다.

가장 안전한 결론은 이렇다. FixAnything은 저자 평가에서 네 3D representation의 render를 하나의 LoRA로 복원했고, clean anchor와 pose-based Flow-DPO가 content preservation과 view consistency를 개선했다. 그러나 고친 영상은 실제 3D geometry의 정답이 아니며, 독립 재현과 현장 데이터 검증 전에는 시각화·콘텐츠 제작용 결과와 계측용 결과를 분리해야 한다.

13. 실무에서 어떻게 시험할까

가장 가까운 용도는 적은 사진으로 만든 scene을 사람이 둘러볼 수 있는 영상으로 정리하는 작업이다. Digital twin preview, AR/VR 배경, 부동산·공간 기록, 로봇 학습용 scene visualization처럼 photorealistic novel view가 필요하지만 모든 영역의 metric geometry가 필수는 아닌 경우에 맞는다.

  1. 같은 scene의 사진을 시간·노출이 크게 다르지 않게 촬영한다.
  2. COLMAP·MapAnything·3DGS 등으로 camera pose와 최소한의 3D scaffold를 만든다.
  3. Training view를 반드시 통과하는 61-frame camera path를 렌더링한다.
  4. 실제 촬영 view의 frame index만 anchor mask로 지정한다.
  5. 먼저 5·10 step으로 seed를 여러 개 시험하고, 중요한 결과만 25·50 step으로 비교한다.
  6. 원본 anchor 보존, frame flicker, object drift, camera pose recovery를 함께 검사한다.
  7. 3D asset이 필요하면 복원 video를 별도 reconstruction pipeline에 넣고 geometry metric을 다시 평가한다.

자사 PoC에서는 PSNR만 보지 말고 anchor pixel change, LPIPS, COLMAP registered-frame ratio, pose AUC, seed 간 variance, 61-frame latency를 같이 기록하는 편이 좋다. 설비 결함이나 안전 영역이라면 생성된 부분을 색으로 표시하고 원본 관측이 없는 영역을 사람이 확인할 수 있어야 한다.

14. 코드·가중치·라이선스 상태

2026년 8월 26일 기준 공식 GitHub에는 실행 가능한 inference code, 3DGS·sparse point 예제, model downloader와 자체 사진을 처리하는 MapAnything wrapper가 있다. Repository는 Python 3.10과 CUDA용 설치법, 61-frame 입력 형식, anchor index 옵션을 문서화했다.

Hugging Face model card에는 rank-64 fixanything_lora.safetensors가 공개됐다. LoRA만으로는 실행할 수 없고 Wan2.1-I2V-14B-480P base model을 별도로 내려받아야 한다. 공식 downloader는 base checkpoint를 약 60GB로 안내한다.

코드와 FixAnything weight는 Apache-2.0이며 Wan2.1 model card도 Apache-2.0이다. 논문 자체는 arXiv perpetual non-exclusive license다. 선택 설치 항목인 MapAnything, DiffSynth-Studio, gsplat, DL3DV 데이터와 사용자가 투입하는 촬영물은 각각의 라이선스·개인정보 조건을 별도로 확인해야 한다.
