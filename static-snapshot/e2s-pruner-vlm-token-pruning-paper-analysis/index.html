E2S-Pruner 논문 분석: 학습 없이 VLM Visual Token을 줄이는 Evidence Fusion

이미지·prompt와 VLM attention을 받아 head·layer evidence를 결합하고 token을 줄이는 과정, 여섯 benchmark의 유지율과 latency·memory·OCR 한계를 분석합니다.

같은 이미지를 본 attention head들이 서로 다른 곳을 중요하다고 말할 때, 점수를 평균내는 것이 정말 안전할까? E2S-Pruner는 이 불일치를 잡음으로 지우지 않고 증거의 불확실성과 충돌로 모델링한다. 추가 학습 없이 LLM 내부의 visual token을 단계적으로 줄이되, 서로 다른 head와 layer가 지지한 정보를 Dempster–Shafer evidence theory로 결합하는 방식이다.

논문은 LLaVA-1.5-7B의 평균 visual-token budget을 128과 64로 줄였을 때 MMBench 평가 환경에서 throughput이 각각 1.96배와 2.09배가 됐다고 보고한다. 하지만 aggressive pruning은 작은 글자에 약하고, peak GPU memory는 dense model보다 약 21% 늘었다. 더 중요한 해석상의 주의점도 있다. 논문의 “64 tokens”는 마지막까지 64개를 유지한다는 뜻이 아니라 32개 LLM layer 전체에서 평균한 budget이다.

정식 제목: E2S-Pruner: Progressive Two-Stage Evidence Fusion for Visual Token Pruning in Vision-Language Models · arXiv: 2608.23253v1 · 제출: 2026년 8월 24일 13:44:41 UTC · 확인 기준: 2026년 8월 26일

1. 어떤 문제를 풀려는 논문인가

VLM은 vision encoder가 이미지를 여러 patch token으로 바꾼 뒤 text token과 함께 LLM에 넣는다. LLaVA-1.5-7B의 논문 설정에서는 이미지 한 장이 24×24, 즉 576개 visual token이 된다. 이 token이 LLM의 모든 layer를 지나면 self-attention과 feed-forward 계산, activation과 KV 관련 memory 부담이 커진다.

일반적인 attention pruning은 text가 많이 바라보는 visual token을 중요하다고 보고 score를 평균한 뒤 Top-K만 남긴다. 문제는 head와 layer마다 역할이 다르다는 데 있다. Shallow layer는 texture와 edge, middle layer는 object structure, deep layer는 global semantics에 더 반응할 수 있다. 어떤 token이 한 layer에서는 약하지만 다른 layer에서는 강한 증거를 얻었을 때 단순 평균은 그 이유와 충돌을 구분하지 못한다.

E2S-Pruner의 질문은 “점수가 얼마나 큰가”에서 “그 점수를 낸 증거가 얼마나 명확하고 서로 일치하는가”로 바뀐다. 여러 head가 비슷한 방향을 지지하면 reliability를 높이고, head끼리 엇갈리면 일부 mass를 uncertainty에 남긴다. Layer끼리 의견이 충돌한 token은 바로 버리지 않고 retention priority를 올려 보호한다.

Training-free의 정확한 뜻

이 논문에서 training-free는 E2S-Pruner를 위해 별도 model을 학습하거나 base VLM을 fine-tuning하지 않는다는 뜻이다. 추가 weight나 전용 checkpoint도 필요하지 않다. 이미 학습된 LLaVA-1.5-7B 또는 Qwen2-VL-7B의 inference graph 안에서 attention을 읽고 token index를 선택한다.

  • Base VLM 자체는 대규모 데이터로 사전학습된 모델이다.
  • Pruning layer, 단계별 keep count, spatial grid와 λ는 사람이 설정한다.
  • Evidence fusion 계산과 intermediate tensor는 추가된다.
  • 모델 내부 Q·K 또는 head별 attention에 접근해야 하므로 closed VLM API에 설정 하나로 붙이는 방식은 아니다.

2. Input — 무엇을 받아 token을 고르는가

이미지와 사용자 질문

사용자 수준의 입력은 일반 VLM과 같다. 이미지와 “표지판에 무엇이라고 쓰였나?”, “사진 속 동물은 몇 마리인가?” 같은 text prompt를 넣는다. Vision encoder는 이미지를 visual token 집합으로 만들고 tokenizer는 질문을 text token 집합으로 만든다.

E2S-Pruner는 image saliency만 보는 방법이 아니다. 각 LLM head에서 모든 text token의 query와 visual token의 key 사이 scaled dot product를 평균해 text-to-visual attention evidence를 만든다. 같은 이미지라도 질문이 달라지면 text query가 달라지므로 남는 visual token도 달라질 수 있다.

모델 내부에서 필요한 정보

  • 현재 layer의 visual-token activation과 원래 2D patch 위치
  • 각 attention head의 text query와 visual key
  • 이전 pruning layer까지 누적한 token별 D-S mass
  • Pruning layer 목록과 각 단계의 keep budget

LLaVA 실험은 32-layer LLM에서 layer 3, 17, 22를 통과한 뒤 세 번 pruning한다. 따라서 layer 4, 18, 23의 입력 visual-token 수가 단계적으로 줄어든다. 이 위치는 학습으로 찾는 것이 아니라 논문 설정으로 고정한다.

3. Output — 무엇이 나오고 무엇은 나오지 않나

E2S-Pruner 자체의 직접 출력은 각 pruning 시점에 계속 전달할 visual-token index와 token subset이다. 선택되지 않은 token은 이후 LLM layer에서 제거된다. 남은 token과 text representation으로 base VLM이 원래와 같은 자연어 답변을 만든다.

  • 최종 사용자 출력 형식은 base VLM의 text answer와 같다.
  • D-S uncertainty는 token selection용 내부 값이며, 답변의 calibrated confidence로 출력되지 않는다.
  • 삭제한 patch를 OCR detector로 복구하거나 고해상도로 다시 읽는 fallback은 없다.
  • Token merging처럼 제거 token의 feature를 보존 token에 합치는 것이 아니라 Top-K 밖 token을 prune한다.

따라서 성능 손실은 “답변 생성 능력이 새로 학습되지 않아서”가 아니라, 뒤쪽 layer가 더 이상 볼 수 없는 visual evidence가 생겨서 발생한다. 작은 글자나 얇은 선처럼 한두 patch에 정보가 몰린 task에서 특히 위험하다.

4. ‘192·128·64 tokens’는 실제로 무엇을 뜻하나

논문은 방법마다 pruning 위치와 최종 token 수가 다르기 때문에 AvgTokens를 비교 기준으로 쓴다. 각 LLM layer에 들어간 visual-token 수를 모두 더한 뒤 전체 32개 layer로 나눈 값이다. 즉 average budget 64는 모든 layer에서 64개를 유지한다는 설정이 아니다.

AvgTokens = (각 LLM layer가 처리한 visual-token 수의 합) / LLM layer 수

64-budget에서는 layer 22 뒤에 visual token이 0개다. 이후 layer는 앞선 layer에서 image information이 섞인 text representation만 이어서 처리한다. “576개를 64개로 줄여 마지막까지 64개가 남는다”는 요약과 실제 계산 graph가 다른 이유다.

Baseline과의 공정성도 이 평균 budget 안에서 해석해야 한다. 논문은 서로 다른 pruning schedule을 같은 AvgTokens로 맞췄지만, 모든 방법이 같은 layer에서 같은 최종 token 수를 쓰는 것은 아니다.

5. Process — attention에서 Top-K token까지

Step 1. Head별 text-to-visual attention 계산

Pruning layer l의 head h에서 visual token n이 받은 score는 모든 text token의 query와 해당 visual key의 scaled dot product를 평균한 값이다. 그 뒤 같은 head 안의 visual-token 축으로 softmax해 상대 attention r(l,h,n)을 만든다.

a(l,h,n) = mean_text(Q_text · K_visual(n) / sqrt(d))
r(l,h,n) = softmax_over_visual_tokens(a(l,h,n))

Step 2. Attention을 0.5 기준의 support로 변환

현재 visual-token 수를 N이라고 하면 support는 p = N·r / (1 + N·r)로 바꾼다. 모든 token이 균등 attention 1/N을 받으면 p=0.5다. 0.5보다 크면 보존 쪽, 작으면 제거 쪽의 증거로 읽고, 값은 0 이상 1 미만 범위에 놓인다.

이 변환은 서로 다른 pruning stage에서 token 수가 바뀌어도 “평균 attention”을 같은 0.5 기준으로 맞추려는 장치다. Raw attention magnitude를 layer 사이에서 바로 더하는 방식과 차이가 있다.

Step 3. Head들의 명확성과 일치도로 reliability 계산

한 token에 대해 여러 head의 support가 0.5에서 멀고 같은 방향을 가리키면 증거가 명확하고 일관적이다. 반대로 일부 head는 0.9, 일부는 0.1이라면 평균만으로는 보존 여부를 결정하기 어렵다. E2S-Pruner는 decision clarity와 head support의 평균 편차로 만든 consistency를 곱해 reliability ρ를 만든다.

여기서 첫 단계는 각 head를 Dempster rule로 하나씩 결합하는 구현이 아니다. Head별 support의 평균과 head 간 명확성·일치성으로 하나의 layer-wise mass function을 구성한다. Dempster–Shafer의 명시적인 recursive combination은 다음 layer-fusion 단계에서 수행된다.

Step 4. Important·Unimportant·Uncertain mass 구성

Token n의 head-average support를 p̄라고 하면 layer l의 mass는 다음과 같다.

m(I) = ρ · p̄
m(U) = ρ · (1 - p̄)
m(Θ) = 1 - ρ

I는 important, U는 unimportant다. Θ={I,U}는 “중요하거나 중요하지 않을 수 있으나 현재 증거로 구분할 수 없음”에 배정한 mass다. 즉 uncertain은 I·U와 나란히 놓인 세 번째 독립 class가 아니라 두 가설을 포괄하는 ignorance set이다.

Step 5. Dempster–Shafer로 layer 증거를 재귀 결합

첫 pruning layer의 mass를 시작점으로 두고, 다음 pruning layer가 올 때마다 이전 누적 mass와 현재 mass를 합친다. 두 source의 직접 충돌은 이전이 important인데 현재가 unimportant인 경우와 그 반대의 곱을 더해 계산한다.

K = m_prev(I)·m_now(U) + m_prev(U)·m_now(I)

Bel(I) = m_fused(I)
Pl(I)  = m_fused(I) + m_fused(Θ) = 1 - m_fused(U)

Dempster’s rule은 서로 모순되지 않는 조합의 mass를 더하고 1-K로 정규화한다. Belief는 중요하다고 직접 지지된 mass의 하한이고, plausibility는 uncertainty까지 포함해 “중요할 가능성을 아직 배제할 수 없는” 상한이다. E2S-Pruner는 보수적으로 Bel이 아니라 Pl을 pruning 기준에 쓴다.

Step 6. Layer conflict가 큰 token을 보호

최종 retention priority는 다음 식이다.

q = 1 - (1 - Pl(I)) · (1 - K)

중요 plausibility가 높거나, 이전·현재 layer의 판단 충돌 K가 크면 q가 올라간다. Layer끼리 의견이 다르다는 이유로 평균 score가 낮아진 token을 즉시 지우지 않고 다음 layer까지 보존하려는 conflict protection이다. 이 uncertainty는 답변 확률을 보정하는 것이 아니라 token 삭제 결정을 늦추는 데 쓰인다.

Step 7. Spatial novelty bonus 뒤 global Top-K

Semantic relevance만으로 global Top-K를 하면 한 물체 주변에 token이 몰릴 수 있다. LLaVA의 24×24 patch grid를 4×4 spatial cell로 나누면 cell 하나에는 처음에 6×6 token이 들어간다. 각 occupied cell에서 q가 가장 높은 대표 token 하나에 indicator b=1을 주고, λ=0.1의 soft bonus를 더한다.

q_spatial = (1 - λ)·q + λ·b,  λ = 0.1

이것은 각 cell에서 반드시 하나를 남기는 hard quota가 아니다. 대표 token의 순위를 조금 올린 뒤 전체 후보에서 다시 Top-K를 고른다. 따라서 coverage를 유도하지만 모든 공간 영역 보존을 보장하지 않고, 글자가 있는 cell을 특별히 인식해 보호하지도 않는다.

6. Dempster–Shafer 결합이 단순 평균과 다른 이유

가령 작은 표지판 token을 shallow layer는 0.02로 거의 무시하지만 middle·deep layer는 0.65와 0.62로 지지한다고 하자. 단순 평균은 0.43이 되어 쉽게 잘릴 수 있다. E2S-Pruner는 각 layer의 reliability와 uncertainty를 따로 남기고, shallow와 deep evidence가 충돌했다는 K까지 retention score에 반영한다.

이 설계의 장점은 “모든 layer가 동의한 token”뿐 아니라 “어떤 layer에서는 강한데 다른 layer에서는 판단이 보류된 token”을 살릴 여지가 있다는 것이다. 반면 높은 conflict가 항상 유용한 정보라는 보장은 없다. 잡음 때문에 layer 의견이 갈린 token도 추가로 보호될 수 있으므로, 실제 이득은 ablation과 task별 결과로 확인해야 한다.

7. 어떤 데이터셋으로 평가했나

LLaVA-1.5-7B의 main 비교는 GQA, SQA, TextVQA, POPE, MME, MMBench 여섯 개다. Qwen2-VL-7B cross-model 비교는 SQA, POPE, MME, AI2D 네 개다. 논문은 각 benchmark의 공식 prompt template과 evaluator를 사용했다고 밝힌다.

Aggregate retention은 accuracy가 아니다

여섯 benchmark는 score 단위가 다르므로 각 pruned score를 dense baseline score로 나눈 뒤 여섯 비율을 동일 가중 평균한다. Dense LLaVA의 기준값은 GQA 61.9, SQA 69.5, TextVQA 58.2, POPE 85.9, MME 1862, MMBench 64.6이다.

따라서 “90.6% performance retention”은 문제 100개 중 90.6개를 맞혔다는 accuracy가 아니다. 서로 다른 여섯 metric의 dense 대비 비율 평균이다. 특정 task가 크게 떨어져도 다른 task가 버티면 aggregate가 높게 나올 수 있어 개별 score를 함께 봐야 한다.

8. LLaVA-1.5-7B 비교 결과

논문 비교표에서는 세 average budget 모두 E2S-Pruner의 aggregate retention이 가장 높다. Budget이 작아질수록 V2Drop·SparseVLM과의 차이가 커져, evidence fusion의 이득이 aggressive pruning에서 더 두드러진다. 128-budget에서는 여섯 benchmark 모두 표의 다른 pruning method보다 높은 개별 score를 기록했다.

하지만 192-budget에서는 POPE와 MME가 V2Drop보다 낮다. E2S-Pruner는 POPE 83.6 대 85.1, MME 1814 대 1826이고, aggregate만 98.0 대 97.6으로 높다. “모든 budget의 모든 task에서 최고”가 아니라 세 budget의 정규화 평균에서 최고라고 한정해야 한다.

가장 공격적인 64-budget의 실제 score

E2S-Pruner는 TextVQA를 제외한 다섯 task와 aggregate에서 이 표의 pruning baseline보다 높다. 특히 V2Drop 대비 GQA +5.0, POPE +3.4, MME +186, MMBench +2.1이다. 반면 TextVQA는 뒤집힌다. 이 한 열이 실무에서 중요한 한계를 보여준다.

9. OCR 한계 — 작은 글자는 왜 먼저 사라지나

64 average-token budget에서 E2S-Pruner의 TextVQA는 49.5다. Dense LLaVA 58.2의 약 85.1%이며, LLaVA-PruMerge 54.0보다 4.5점 낮다. 전체 평균은 E2S-Pruner가 높아도 scene-text task만 보면 다른 선택이 더 낫다.

문자는 물체 전체보다 훨씬 작은 patch에 정보가 몰리고 획 하나가 빠져도 의미가 달라진다. 64-budget schedule은 첫 pruning부터 576개를 20개로 줄이고 마지막에는 visual token이 0개가 된다. Spatial novelty는 4×4 cell의 대표 token에 bonus를 줄 뿐 text region을 검출하거나 문자 patch를 묶어서 보존하지 않는다.

128-budget의 default schedule에서는 TextVQA가 56.0으로 dense 58.2에 비교적 가깝고, 같은 표의 pruning 방법 중 가장 높다. 논문의 schedule analysis에서도 deep layer에 42 token을 남긴 기본 schedule이 TextVQA 56.0으로, deep token을 32·22·12·2개로 더 줄인 대안의 55.9·55.6·55.6·55.8보다 높았다. OCR 서비스라면 64-budget headline보다 128 이상에서 text-heavy validation을 먼저 수행하는 편이 합리적이다.

  • 상품 라벨·영수증·문서 OCR은 TextVQA와 별도 내부 benchmark를 둔다.
  • 문자 크기, 저대비, 기울기, 여러 줄 text 조건으로 retention을 나눠 본다.
  • OCR 질문에는 pruning budget을 높이거나 text detector 기반 보호 규칙을 별도로 검토한다.
  • 일반 VQA 평균이 유지돼도 serial number 한 글자 오류는 제품상 실패로 계산한다.

10. Qwen2-VL-7B에서도 통했나

66.7% reduction에서 E2S-Pruner의 98.9%는 V2Drop 97.6보다 +1.3%p, 77.8%에서는 95.4 대 94.9로 +0.5%p다. 별도 fine-tuning 없이 다른 model family에도 적용했다는 점은 의미가 있다.

다만 두 번째 조건에서 E2S-Pruner가 이긴 개별 task는 SQA뿐이다. POPE, MME, AI2D는 V2Drop이 더 높고, 큰 SQA 차이가 정규화 평균을 끌어올린다. Cross-model 검증도 Qwen2-VL-7B 한 모델과 네 benchmark에 한정되며, Qwen에서의 latency·memory 표는 없다. “모든 VLM에서 같은 2.09×”로 일반화할 수 없다.

11. Ablation — 어떤 구성요소가 필요했나

일반 attention Top-K를 full E2S로 바꾸면 네 task의 정규화 retention이 92.9→97.7%, +4.8%p다. Head reliability는 +1.9%p, layer-wise fusion은 +1.5%p, conflict protection은 +0.9%p, spatial novelty는 +1.4%p의 차이를 보인다.

Full model이 모든 개별 metric에서 최고는 아니다. Conflict protection을 뺀 variant의 MME 1781은 full 1779보다 2점 높다. 저자 해석처럼 conflict protection의 장점은 한 benchmark의 절대 최고보다 여러 task에서의 균형에 가깝다.

이 ablation의 Avg는 SQA·TextVQA·MME·MMBench 네 task만 평균한 97.7%다. Main Table의 여섯 task aggregate 96.8%와 계산 대상이 다르므로 서로 바꾸어 인용하면 안 된다. 논문은 반복 seed의 평균·표준편차나 confidence interval도 보고하지 않는다.

12. 지연·throughput·memory의 실제 trade-off

효율성 표는 논문 표기상 NVIDIA GeForce RTX 4080 Super GPU, 32GB memory에서 MMBench를 사용해 측정했다. GPU 수, batch size, warm-up, decoding length와 generation parameter는 별도로 제시되지 않는다. 아래 latency는 수백 초 단위의 평가 실행 총량으로 보고돼 있어 단일 request latency로 읽으면 안 된다.

속도는 좋아지지만 memory-efficient는 아니다

128-budget은 MMBench score를 64.6→63.5로 비교적 적게 낮추면서 total latency를 48.5% 줄인다. 64-budget은 throughput을 11.02 item/s까지 높이지만 score가 57.3으로 더 떨어진다. 이 표에서 128은 quality-speed 균형, 64는 최대 throughput 쪽에 가깝다.

반면 peak memory는 dense 15,566MB에서 약 18.8GB로 늘어난다. 논문은 evidence modeling과 cross-layer fusion을 위해 보존한 intermediate state가 원인이라고 설명한다. E2S-Pruner의 peak memory는 SparseVLM보다는 조금 낮지만 FastV와 V2Drop보다 높다. Visual-token 수를 줄였다는 이유만으로 저메모리 edge 배포에 적합하다고 결론낼 수 없다.

또 2.09×는 같은 MMBench 환경에서 dense LLaVA 대비 throughput 비율이다. Vision encoder, prompt 길이, 생성 답변 길이와 kernel 구현이 다른 서비스에서 그대로 재현된다는 보장은 없다. 코드가 비어 있는 현재는 저자 측정 protocol을 독립 확인할 수도 없다.

13. 이 논문의 장점

  • 추가 학습이 없다. Base VLM을 다시 fine-tuning하거나 pruning network를 따로 학습하지 않는다.
  • Head와 layer의 차이를 명시적으로 다룬다. Attention 평균 하나로 줄이기 전에 clarity, consistency, uncertainty와 conflict를 계산한다.
  • 갈등을 삭제 근거로만 보지 않는다. Layer 사이의 높은 conflict를 잠재적으로 중요한 증거로 보고 보존 priority에 반영한다.
  • 공간 쏠림을 완화한다. 학습 가능한 detector 없이 patch grid의 cell 대표 token에 soft bonus를 준다.
  • 실제 wall-clock throughput 향상을 보고했다. FLOPs 추정에 그치지 않고 MMBench에서 total latency와 item/s를 함께 제시한다.
  • 두 model family에서 aggregate 우위를 보였다. LLaVA-1.5-7B와 Qwen2-VL-7B 모두 저자 비교표의 정규화 평균이 가장 높다.
  • Ablation의 비교 축이 분명하다. Head reliability, layer fusion, conflict protection, spatial novelty를 같은 128-budget에서 각각 제거했다.

14. 한계와 결과 해석의 경계

  • 64는 final token 수가 아니다. LLaVA의 average budget이며 실제 schedule은 576→20→8→0이다.
  • OCR·작은 문자에 약하다. 64-budget TextVQA 49.5는 LLaVA-PruMerge 54.0보다 4.5점 낮다.
  • Spatial novelty는 hard coverage가 아니다. 각 cell 대표에 bonus만 주므로 text·작은 물체 보존을 보장하지 않는다.
  • Peak memory가 늘어난다. 128·64 budget 모두 dense보다 약 21% 높은 약 18.8GB를 쓴다.
  • 효율성 조건이 충분히 공개되지 않았다. Batch, warm-up, output length와 정확한 latency 측정 절차가 없다.
  • Aggregate retention은 개별 능력을 숨길 수 있다. Qwen 77.8% reduction에서 SQA는 강하지만 POPE·MME·AI2D는 V2Drop보다 낮다.
  • 모든 VLM으로 일반화된 것은 아니다. 7B급 LLaVA와 Qwen 한 모델씩이며 Qwen 효율성 수치는 없다.
  • Closed API에는 바로 붙일 수 없다. Head별 내부 attention과 중간 layer에서 token을 제거할 수 있어야 한다.
  • 통계적 불확실성이 보고되지 않았다. 반복 실행 분산과 confidence interval 없이 저자 단일 표로 비교한다.
  • 독립 재현 전이다. 논문이 code available이라고 적었지만 공식 저장소가 비어 있어 결과를 실행해 볼 수 없다.

15. 실무에서는 어떻게 검증해야 하나

적용 후보는 open-source VLM을 직접 운영하면서 GPU 처리량이 병목인 서비스다. 일반 image QA, 상품 image 분류 보조, multimodal agent의 screen understanding처럼 질문별로 필요한 영역이 달라질 때 prompt-conditioned pruning이 유용할 수 있다.

  • 1단계: Dense, avg 192, avg 128, avg 64를 같은 GPU와 decoding setting에서 비교한다.
  • 2단계: 전체 평균 외에 OCR, counting, small object, chart, hallucination을 별도 slice로 나눈다.
  • 3단계: p50·p95 request latency, time-to-first-token, output token/s, peak memory를 함께 측정한다.
  • 4단계: 같은 image에 질문을 바꿨을 때 남는 patch와 답변 안정성을 확인한다.
  • 5단계: Memory가 제약이면 E2S와 FastV·V2Drop을 accuracy뿐 아니라 동시 처리 가능한 batch로 비교한다.

문서·라벨·부품 각인처럼 작은 글자가 핵심이면 64-budget을 기본값으로 삼기 어렵다. 128 또는 192부터 시작하고, text region이 감지되면 pruning을 완화하는 routing이 필요하다. 반대로 POPE나 일반 object reasoning이 주된 workload라면 aggressive setting도 후보가 될 수 있지만 실제 false-positive cost를 별도로 봐야 한다.

M1 Pro 같은 Apple Silicon에서는 현재 성능을 예측할 근거가 없다. 논문은 CUDA GPU 환경만 보고했고 official code가 없다. Attention kernel에서 head별 Q·K를 노출하고 중간 sequence length를 동적으로 바꾸는 구현이 Metal backend에서 효율적으로 동작하는지도 확인해야 한다.

16. 코드·라이선스·재현 가능성

논문 초록은 code가 공식 GitHub에 있다고 적는다. 그러나 2026년 8월 26일 확인 기준 repository 화면은 “This repository is empty”이며, Git remote에도 branch나 commit reference가 없다. README, source, config, requirements, test script가 모두 없는 상태다.

별도 학습 weight가 필요 없는 방법이므로 E2S 전용 checkpoint 미공개는 문제가 아니다. 재현을 막는 것은 layer hook, attention 추출, token position 관리, Qwen 적용, latency 측정 script 같은 실제 구현이 없다는 점이다. 특히 optimized attention kernel과 KV cache에서 token을 어떻게 제거했는지 확인할 수 없다.

빈 repository에는 software LICENSE도 없다. 따라서 향후 올라올 구현의 사용·수정·상업 이용 조건은 아직 미정이다. 논문은 arXiv perpetual non-exclusive license로 배포됐으며, LLaVA·Qwen·vision encoder와 각 benchmark data에는 별도 license가 적용된다.
