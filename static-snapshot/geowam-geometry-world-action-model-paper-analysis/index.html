GeoWAM 논문 분석: 미래 RGB 대신 3D Geometry를 예측해 주행하는 World Action Model

Historical multiview RGB에서 future point map과 ego trajectory를 만드는 두 단계 학습, pretraining 데이터와 nuScenes·NAVSIM v2 결과를 분석합니다.

자율주행 world model이 미래 도로의 RGB 영상을 그려야만 장면 변화를 배울 수 있을까? GeoWAM은 그 중간 표현을 픽셀에서 3D point map으로 바꾼다. 과거의 여러 카메라 영상을 보고 앞으로 4초 동안의 metric geometry를 예측한 뒤, 그 변화에 조건을 걸어 한 개의 ego trajectory를 회귀한다.

이 글은 GeoWAM: Visual Geometry World Action Models for Autonomous Driving의 Input·Process·Output을 학습과 추론 순서대로 풀어본다. Geometry target을 어떻게 만들고 어떤 데이터로 pretraining했는지, nuScenes의 미래 geometry와 NAVSIM v2 planning 결과가 정확히 무엇을 뜻하는지, 공개 코드가 없는 현재 어디까지 재현할 수 있는지도 함께 살펴본다.

1. 왜 미래 RGB 대신 미래 geometry인가

대부분의 driving world model은 과거 영상을 바탕으로 미래 영상을 생성한다. 이 방식은 차의 움직임과 도로 구조뿐 아니라 색, 그림자, 날씨, 재질, 카메라 노이즈까지 픽셀에 함께 맞춰야 한다. 시각적으로 그럴듯한 영상이 나와도 그 안의 3D 이동과 충돌 여유가 planner가 바로 쓰기 좋은 형태로 분리됐다고 보장할 수는 없다.

GeoWAM의 주장은 geometry가 driving action과 더 가까운 state space라는 것이다. Point map은 각 pixel이 대응하는 3D 점을 metric 공간에 놓는다. 시간에 따라 이 점들이 바뀌는 모습에는 ego vehicle의 움직임, 다른 차량의 이동, 정적 구조가 직접 드러난다. 따라서 미래의 외관을 합성하기보다 미래의 공간 구조를 예측하게 하면 planning에 필요한 representation을 더 곧게 학습할 수 있다는 가설이다.

여기서 GeoWAM은 미래 point cloud를 action으로 조건화해 생성하는 simulator라기보다, 관측된 과거로부터 미래 geometry를 먼저 예측하고 그 geometry로 ego motion을 추론하는 policy에 가깝다. 논문도 이 연결을 inverse-dynamics-like formulation이라고 표현한다.

2. Input — 모델이 실제로 받는 것

과거 3개 시점의 multi-view RGB

입력은 I[t-K+1:t]로 표기되는 시간 순서의 camera image 묶음이다. 각 시점에는 V개 camera view가 있고 한 장의 형태는 3×H×W다. 구현에서 K=3이므로 모델은 현재를 포함한 최근 3개 multi-camera frame을 본다.

Geometry pretraining 중에는 각 sequence에서 2~8개 camera view를 동적으로 sampling한다. 서로 다른 dataset의 camera rig와 view 수가 달라도 하나의 모델에 넣기 위한 선택으로 읽을 수 있다. Planning fine-tuning에서는 NAVSIM navtrain의 8개 camera view와 과거 3개 frame을 고정해 사용한다.

미래 RGB는 추론 입력이 아니다. 학습할 때만 정답 시점의 RGB를 target branch에 넣어 feature target을 만든다. Forecasting branch는 과거 영상만 보고, 배포 시점에도 미래 영상이나 LiDAR를 요구하지 않는다.

입력에 관해 논문이 밝히지 않은 것

논문에는 image resolution, camera별 resize·crop, augmentation, calibration을 token에 넣는 방식, dataset 간 camera mapping이 적혀 있지 않다. 2~8 view sampling이 어느 확률로 이뤄지는지와 3개 history frame의 실제 시간 간격도 명시되지 않는다. 구조를 이해하기에는 충분하지만, 같은 tensor를 만들어 수치를 재현하기에는 중요한 빈칸이다.

3. Output — geometry와 action을 따로 보자

Output A. 미래 dense point map

미래 시점 t+k마다 모델은 V×H×W×3 크기의 point map과 V×H×W confidence map을 출력한다. 각 image pixel에 3차원 좌표 하나를 대응시키며, 좌표는 해당 미래 시점 t+k의 ego coordinate system으로 표현된다. 미래 RGB, semantic class, occupancy voxel을 직접 출력하는 구조는 아니다.

F=8, sampling rate는 2Hz이므로 예측 시점은 0.5초 간격으로 8개, 마지막은 4초 뒤다. 논문 표의 1·2·3·4초 수치는 그중 네 시점을 보여주며, mean은 이 네 숫자의 평균이 아니라 0.5초부터 4초까지 여덟 frame 전체의 평균이다.

Output B. 하나의 deterministic ego trajectory

Action head는 미래 8개 시점 각각에 대해 (x, y, θ)를 예측한다. x, y는 planar position, θ는 heading이며 모두 현재 ego coordinate frame을 기준으로 한다. 결과는 한 개의 연속 trajectory다.

Trajectory anchor, mode classification, diffusion sampling, 여러 후보의 ranking이 없다. 계산 경로는 단순하지만 교차로나 가려진 상대 차량처럼 미래가 본질적으로 여러 갈래인 장면에서 uncertainty를 직접 표현하지 못한다.

4. Process — 미래 공간을 만들고 주행 경로로 바꾸는 과정

Step 1. DVGT-2 encoder가 history를 두 종류의 token으로 변환

Geometry encoder는 DVGT-2에서 초기화한다. 선택한 여러 feature level마다 각 과거 시점과 camera view에서 두 종류의 token을 낸다.

  • Geometry token X: view마다 P=h×w개의 spatial token으로 장면 구조를 표현한다.
  • Ego token E: view마다 N_e개의 token으로 observation history의 ego-motion context를 표현한다.

두 token을 이어 붙인 뒤 과거 시간과 feature level 전체를 historical geometry memory Z로 보존한다. 이후 geometry branch와 action branch가 이 memory를 공통으로 참조한다.

Step 2. 미래의 시간·view·공간 위치마다 geometry query를 배치

하나의 learned geometry-query seed를 미래 시점, camera view, spatial location마다 복제한다. 여기에 미래 time embedding, view embedding, 2D sinusoidal positional embedding을 더한다. Query는 아직 미래 장면을 담고 있지 않고 “어느 시점의 어느 카메라에서 어느 위치를 예측할 것인가”를 나타내는 빈 슬롯이다.

Step 3. 6-layer decoder가 시간 변화와 과거 관측을 결합

Future geometry decoder는 6개 Transformer layer, hidden dimension 1024, 16 attention head로 구성된다. 각 layer는 두 연산을 반복한다.

  1. Causal temporal self-attention: 같은 spatial location의 미래 8개 query 사이에서 앞선 미래 시점만 보며 scene evolution을 모델링한다.
  2. Cross-attention: 갱신된 query가 과거 geometry memory에서 관련 관측을 가져온다.

마지막 future latent를 feature level별 projection으로 DVGT-2 geometry head가 요구하는 차원에 맞춘다. Shared Point DPT head가 이 multi-level representation을 dense point map과 confidence map으로 decoding한다.

Step 4. 미래 RGB에서 feature target을 만들되 gradient는 끊는다

학습 시 실제 미래 RGB를 같은 geometry encoder의 target branch에 통과시켜 feature level별 patch target을 만든다. 이 target은 computation graph에서 detach한다. 예측 feature와 target feature의 cosine distance를 평균한 L_feat가 future latent를 실제 미래 장면의 geometry representation에 맞춘다.

동시에 미래 point map에는 valid pixel만 골라 세 항을 적용한다. Euclidean point regression, confidence-aware regression, multi-scale surface-normal consistency다. 현재 frame에도 같은 point-map objective를 걸어, 미래 예측을 배우는 동안 geometry encoder의 현재 장면 복원 능력이 흐트러지지 않게 anchor를 둔다.

L_pre = L_feat + L_point_future + L_point_current
L_point = L_reg + L_conf + L_normal

Step 5. 예측 geometry로 미래 ego token을 추론

두 번째 학습 단계에서는 미래 시점·view·ego-token slot별 learned ego query를 추가한다. Ego decoder도 먼저 causal temporal self-attention을 수행한 뒤, 과거 memory와 예측된 미래 geometry token을 모두 cross-attention한다. 이 결과가 미래의 ego-motion context를 표현하는 ego token이다.

Future geometry token에서 ego decoder로 향하는 연결에는 stop-gradient가 있다. Trajectory loss가 geometry branch까지 역전파되어 pretraining으로 얻은 예측 공간을 임의로 바꾸지 못하게 한 것이다. 즉 geometry가 action을 조건화하지만 action supervision이 geometry 표현을 다시 빚는 양방향 결합은 아니다.

Step 6. Causal action head가 단일 trajectory를 회귀

가장 깊은 level의 과거 ego token과 예측된 미래 ego token을 시간축으로 붙여 causal temporal Transformer로 정제한다. Learned trajectory query가 이 sequence를 cross-attention하고 regression head가 최종 8-step trajectory를 낸다.

Planning fine-tuning에서도 geometry loss를 버리지 않는다. Trajectory의 L1 loss와 과거 frame 사이 relative pose를 예측하는 auxiliary L1 loss를 더하며, 두 가중치는 각각 5다.

L_plan = L_pre + 5 × L_traj + 5 × L_pose

5. Geometry pseudo-target은 어떻게 만들어지나

논문은 dense metric point-map target을 off-the-shelf geometry foundation model에서 얻는다고 설명한다. 사람이 voxel마다 occupancy label을 붙이거나 LiDAR로 occupancy ground truth를 구축하는 대신, RGB driving frame에 사전학습 geometry model을 실행해 pixel별 3D 좌표와 valid mask를 만들고 이를 supervision으로 쓰는 방식이다. 논문 표현은 point-map target이지만, 외부 모델의 예측을 학습 정답으로 사용한다는 점에서는 pseudo-label 역할을 한다.

이 선택의 실질적인 장점은 geometry pretraining dataset을 RGB log가 있는 곳까지 넓힐 수 있다는 것이다. Occupancy annotation 형식이 서로 다른 일곱 dataset을 하나의 dense point-map prediction 문제로 묶을 수 있다. Future video generation처럼 appearance 전체를 합성하지 않으면서도 camera image만으로 metric scene evolution을 학습한다.

“GT occupancy가 필요 없다”의 정확한 범위

  • 맞는 말: Geometry pretraining에 voxelized ground-truth occupancy annotation을 요구하지 않는다. 미래 geometry target은 RGB에 외부 geometry foundation model을 적용해 얻는다.
  • 과한 해석: 전체 GeoWAM이 label-free이거나 RGB 파일만 있으면 아무 준비 없이 학습된다는 뜻은 아니다. Planning 단계는 ego trajectory label과 historical relative-pose supervision을 사용한다.
  • 남은 의존성: 시간적으로 정렬된 multi-view sequence, dataset별 camera 구성, point-map 생성과 validity filtering pipeline은 여전히 필요하다.

재현에 가장 큰 빈칸도 여기 있다. v2 본문은 target을 만든 geometry foundation model의 정확한 이름과 checkpoint, metric scale 정렬, camera별 preprocessing, confidence threshold, invalid pixel filtering을 공개하지 않았다. Encoder와 point head를 DVGT-2에서 초기화했다고는 적었지만, 그것만으로 모든 target을 DVGT-2가 생성했다고 단정할 수는 없다. 따라서 pseudo-target 품질과 teacher bias가 결과에 미친 영향은 코드 공개 전에는 분리해 검증하기 어렵다.

6. 어떤 데이터로 학습했나

Pretraining은 AdamW, weight decay 0.05, bfloat16으로 161 epoch 수행한다. 새 future decoder의 peak learning rate는 1×10^-4, DVGT-2에서 가져온 component는 2×10^-5다. 첫 5%는 linear warmup, 이후 cosine decay를 쓴다.

Planning은 geometry-pretrained checkpoint에서 시작해 navtrain으로 40 epoch fine-tuning한다. Future decoder와 새 action head는 1×10^-4, 나머지 pretrained parameter는 2×10^-5다. 논문에는 일곱 pretraining dataset의 sample 수, mixture ratio, sampling weight, batch size, GPU 종류·수, 전체 학습 시간, model parameter 수와 FLOPs가 없다. 대규모 mixed-data 학습을 그대로 다시 돌리는 데 필요한 compute budget도 아직 알 수 없다.

7. nuScenes future geometry 평가는 무엇을 재나

예측한 3D point마다 ego-vehicle origin까지의 거리를 계산해 ray depth로 바꾼다. 평가 지표는 다음 두 개다.

  • Abs Rel ↓: reference depth에 대한 절대 오차를 reference depth로 나눈 상대 오차의 평균. 낮을수록 좋다.
  • δ<1.25 ↑: prediction과 reference의 비율 오차가 1.25 threshold 안에 들어온 pixel의 비율. 높을수록 좋다.

비교군의 output을 맞추는 과정이 중요하다. Epona와 Cosmos 3는 미래 RGB를 먼저 생성한 뒤 DVGT로 3D scene을 복원한다. VGGT-World는 geometry foundation model의 feature space에서 미래 geometry를 직접 예측한다. GeoWAM은 미래 point map을 직접 decoding한다. 모두 같은 형태의 geometry metric으로 비교하지만, pipeline과 계산량이 동일한 대조 실험은 아니다.

저자 비교표에서 GeoWAM은 모든 표시 horizon의 Abs Rel이 가장 낮다. 가장 강한 video baseline Epona+DVGT와 비교하면 8-frame mean Abs Rel은 0.274→0.257로 0.017 감소했고, 상대 감소율은 약 6.2%다. Mean δ<1.25는 0.655→0.754로 0.099, 즉 9.9%p 높다. VGGT-World와 비교한 mean Abs Rel 감소율은 약 20.9%다.

그러나 모든 칸에서 1위는 아니다. 1초 δ<1.25는 Epona+DVGT 0.732가 GeoWAM 0.708보다 높다. GeoWAM의 차이는 주로 2~4초에서 커진다. 따라서 “짧은 horizon부터 모든 geometry 지표가 우수하다”보다 Abs Rel은 전 horizon에서 가장 낮고, threshold accuracy는 장기 horizon과 전체 평균에서 우세하다가 정확한 요약이다.

평가 reference의 생성 경계도 남는다. v2는 미래 point-map target과 validity mask를 쓴다고 설명하지만, geometry 평가의 reference가 LiDAR ground truth인지 같은 foundation-model target인지 명확하게 식별할 세부 pipeline을 제공하지 않는다. 그러므로 위 수치를 실제 LiDAR 3D 오차라고 바꿔 부르기보다 논문이 정한 future point-map/ray-depth protocol에서의 일치도로 읽어야 한다.

8. NAVSIM v2 navtest — aggregate 90.2를 세부 항목으로 읽기

NAVSIM v2의 EPDMS는 no at-fault collision(NC), drivable-area compliance(DAC), driving-direction compliance(DDC), traffic-light compliance(TLC), ego progress(EP), time-to-collision(TTC), lane keeping(LK), history comfort(HC), extended comfort(EC)를 합친다. 모든 planning metric에는 공식 human-penalty protocol이 적용되며 높을수록 좋다.

GeoWAM의 EPDMS 90.2는 표에서 다음으로 높은 DVGT-2 89.6보다 0.6점 높다. 다만 향상은 모든 component의 동시 상승이 아니다. GeoWAM은 DVGT-2보다 DAC 0.2, EP 0.9, LK 0.3이 낮고 NC·DDC·TLC는 같다. TTC와 HC는 각각 0.1 높으며, 가장 큰 차이는 EC 77.0→86.8의 +9.8점이다.

따라서 저자 표 안에서 aggregate 1위라는 사실은 분명하지만, “geometry forecasting이 모든 안전 항목을 개선했다”는 결론은 이 표가 지지하지 않는다. 또한 DVGT-2는 encoder와 point head의 initialization이지만, GeoWAM과 DVGT-2의 0.6점 차이는 하나의 component만 바꾼 통제 실험이 아니다.

9. NAVSIM v2 navhard — pseudo-closed-loop에서 36.6

navhard는 3D Gaussian Splatting으로 복원한 장면을 이용하는 two-stage pseudo-closed-loop 평가다. Stage 1은 원래 scene을 평가한다. Stage 2에서는 planner가 낸 ego trajectory에 따라 새 camera observation을 렌더링하고, 이를 다음 planning step의 입력으로 되돌린다. 이전 오차가 다음 관측과 예측에 영향을 주므로 한 번만 trajectory를 채점하는 open-loop보다 error recovery를 더 강하게 본다.

GeoWAM은 저자 비교표에서 EponaV2보다 0.5점, DVGT-2보다 4.9점 높은 aggregate를 기록한다. 논문의 † 표시는 reinforcement learning이나 direct PDMS-score supervision을 사용한 방법에 붙으며 GeoWAM에는 붙지 않는다. 저자가 명시한 GeoWAM objective는 geometry loss와 trajectory·pose L1이다.

Aggregate만으로 회복 양상의 모든 측면이 좋아졌다고 보기는 어렵다. 반응형 synthetic scene인 Stage 2에서 GeoWAM과 EponaV2를 비교하면 GeoWAM은 EP 88.9 대 86.0, EC 56.0 대 52.0으로 높다. 반면 NC 80.4 대 83.6, DAC 76.3 대 78.0, DDC 87.3 대 88.0, TTC 76.2 대 80.3 등 여러 항목은 낮다. 36.6은 protocol이 합성한 최종 EPDMS의 우위이지 모든 safety component의 우위를 뜻하지 않는다.

10. Ablation — 현재 논문에는 원인 분해 실험이 없다

2026년 8월 25일의 arXiv v2에는 별도의 ablation section이나 table이 없다. Future geometry를 제거했을 때, feature loss와 point loss 중 하나를 뺐을 때, current-frame anchor 또는 stop-gradient를 없앴을 때, dataset mix와 target generator를 바꿨을 때의 결과가 보고되지 않았다.

논문은 navtest에서 DVGT-2 89.6 대비 GeoWAM 90.2를 강조한다. 하지만 GeoWAM은 DVGT-2 initialization 위에 future-geometry pretraining, 두 decoder, action head, joint fine-tuning objective를 함께 추가한다. 이 비교는 전체 system의 결과 차이는 보여도 0.6점 가운데 얼마가 geometry forecasting 하나에서 왔는지 분리하지 못한다.

세 가지 driving maneuver의 visualization도 정성 근거일 뿐이다. 왼쪽 회전에서 주변 차량의 움직임, 직진 장면에서 도로변 차량을 피하는 trajectory, 도로 표식과 pole의 geometry가 보이지만 세 사례만으로 failure rate나 calibration을 알 수 없다. 저자의 설계 가설은 geometry·planning 두 benchmark에서 일관된 방향을 보였지만, 구성 요소별 인과 효과는 후속 ablation과 독립 재현이 필요하다.

11. 이 논문의 장점

  • World model의 prediction space를 action과 맞춘다. 미래 appearance보다 metric 3D structure를 먼저 예측해 scene dynamics와 ego trajectory를 가까운 좌표 표현에 놓는다.
  • 미래 RGB 합성을 거치지 않는다. GeoWAM은 geometry를 직접 decoding하므로 RGB 생성 후 별도 3D reconstruction을 수행하는 두 단계 pipeline이 필요 없다.
  • Occupancy annotation 의존성을 줄인다. Off-the-shelf geometry model의 point map을 이용해 서로 다른 RGB driving log를 공통 pretraining target으로 묶는다.
  • 미래 표현이 실제 planning까지 이어지는지 함께 평가한다. nuScenes의 geometry accuracy뿐 아니라 NAVSIM v2 navtest와 error feedback이 있는 navhard를 모두 보고한다.
  • Action path가 단순하다. Anchor나 iterative sampling 없이 한 trajectory를 직접 회귀해 복잡한 candidate-selection stage가 없다.
  • Geometry representation을 보호하는 연결이 명확하다. Stop-gradient로 action loss의 역전파 범위를 끊어 pretraining objective와 planning objective의 역할을 구분한다.

12. 한계와 결과 해석의 경계

  • Pseudo-target의 출처와 생성 recipe가 불명확하다. 정확한 geometry foundation model, checkpoint, scale 보정과 validity filtering이 없어 supervision을 재구성하기 어렵다.
  • Teacher error를 그대로 배울 수 있다. 반사면, 먼 거리, moving object, poor overlap에서 geometry foundation model이 틀리면 미래 target도 편향된다. 이에 대한 quality audit가 없다.
  • 단일 trajectory만 낸다. Multimodal future의 확률, 불확실성, 여러 안전 후보를 표현하지 않는다.
  • 행동이 geometry를 다시 조건화하지 않는다. 예측된 미래 장면으로 action을 추론하지만 “이 action을 실행하면 world가 어떻게 바뀌는가”를 반복 rollout하는 action-conditioned simulator는 아니다.
  • 명시적인 ablation이 없다. Geometry objective, decoder, stop-gradient와 mixed dataset 각각의 기여를 분리할 수 없다.
  • 효율성 수치가 없다. Parameter, FLOPs, latency, memory와 point-map decoding 비용이 보고되지 않아 video WAM 대비 계산 이점을 주장할 근거는 아직 없다.
  • 실차 closed-loop가 아니다. navhard는 error feedback을 반영하지만 3DGS 기반 pseudo-simulation이며, 실제 차량과 현실 센서에서의 안전성을 입증하지 않는다.
  • 독립 재현 전의 저자 수치다. Baseline마다 backbone, pretraining data, parameter와 compute budget이 동일하게 통제된 비교는 아니다.

현재 가능한 안전한 결론은 이렇다. GeoWAM은 저자 protocol에서 미래 RGB보다 미래 metric geometry를 직접 예측하는 설계로 낮은 future ray-depth error와 높은 NAVSIM aggregate를 함께 기록했다. 그러나 어떤 구성 요소가 planning 향상의 직접 원인인지, target generator가 바뀌어도 유지되는지, 계산 비용이 실제로 줄어드는지는 아직 검증되지 않았다.

13. 실무에서 어디에 연결할 수 있나

가장 직접적인 응용은 surround-view camera log는 많지만 dense occupancy label이 부족한 자율주행 연구다. 기존 log에 geometry foundation model을 offline으로 적용해 point-map target을 만들고, scene evolution pretraining 뒤 trajectory planner를 붙이는 흐름을 시험할 수 있다.

  • 카메라 기반 자율주행의 0.5~4초 scene-geometry forecasting
  • Warehouse AMR·배송 robot의 통로와 moving agent 예측
  • 공장 이동 설비 주변의 spatiotemporal free-space representation
  • Robot manipulation 영상에서 future object geometry를 action feature로 쓰는 연구

다만 자동차 밖으로 확장하는 부분은 논문이 직접 검증한 결과가 아니라 구조에서 도출한 실무적 가능성이다. Camera motion, workspace scale, deformable object가 달라지면 point-map teacher와 action head를 새로 검증해야 한다.

재현을 시작한다면 먼저 확인할 것

  1. 공식 코드가 공개되면 pseudo-target generator와 metric-scale 정렬 recipe부터 고정한다.
  2. 같은 과거 3-frame·8-future-frame split으로 current reconstruction과 future forecasting error를 따로 측정한다.
  3. DVGT-2 planner, geometry pretraining 없는 action head, full GeoWAM을 같은 data와 compute로 비교한다.
  4. Point-map teacher가 다른 실험과 LiDAR가 있는 subset의 geometry audit를 추가한다.
  5. EPDMS aggregate뿐 아니라 NC·EP·TTC·EC와 corner-case failure를 scenario별로 나눈다.
  6. End-to-end latency에는 encoder, 8-step geometry decoder, Point DPT와 trajectory head를 모두 포함한다.

14. 코드·checkpoint·라이선스 공개 상태

2026년 8월 26일 기준 공식 project page에는 paper와 arXiv link가 공개돼 있다. Page source에는 github.com/vulab-AI/GeoWAM으로 향하는 code button이 TODO comment 상태로 남아 있지만, 해당 repository는 공개 접근 시 404를 반환한다. 실행 가능한 training·inference code와 GeoWAM checkpoint, pseudo-target 생성 script는 확인되지 않는다.

논문은 CC BY 4.0으로 배포된다. Project page footer의 CC BY-SA 4.0 표기는 website source/template에 관한 안내이며, 아직 공개되지 않은 software나 model weight의 license로 볼 수 없다. 향후 repository가 열리면 GeoWAM 자체 license뿐 아니라 DVGT-2, point-map target generator, NAVSIM과 일곱 pretraining dataset의 이용 조건을 각각 확인해야 한다.

구조와 저자 수치는 논문에서 읽을 수 있지만 현재는 독립 재현이 가능한 release 상태가 아니다. Batch size, hardware, image preprocessing, data mixture, target generator가 빠져 있어 공개 code·checkpoint 전에는 동일 수치를 검증했다고 말할 수 없다.
