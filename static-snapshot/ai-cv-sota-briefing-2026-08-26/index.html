AI CV SOTA 브리핑 — E2S-Pruner · FixAnything · GeoWAM (2026.08.26)

학습 없는 VLM token pruning E2S-Pruner, 범용 3D rendering 보정 FixAnything, 미래 geometry로 주행하는 GeoWAM의 입출력·과정·비교 결과와 공개 상태를 검증했습니다.

2026년 8월 26일 수요일 오전. 당시 arXiv cs.CV의 최신 정식 배치였던 8월 25일 공개분은 234편이었다. 최근 24~48시간의 이미지 분류·탐지·세그멘테이션·VLM·비디오·3D 연구를 훑고, 그중 E2S-Pruner·FixAnything·GeoWAM을 골랐다.

세 논문이 겨냥한 병목은 서로 다르다. E2S-Pruner는 VLM이 처리할 visual token을 덜어낸다. FixAnything은 앞서 만든 3D representation의 rendering artifact를 video prior로 보정한다. GeoWAM은 미래 RGB 대신 metric 3D geometry를 예측해 ego trajectory를 만든다.

아래 수치는 논문과 공식 프로젝트가 보고한 결과다. 독립 재현으로 확인된 값은 아직 아니다. 성능 유지율은 여러 benchmark를 dense baseline으로 정규화한 저자 정의 평균일 수 있다. 속도는 특정 hardware·batch·해상도 조건에서 잰 값이다. 숫자 하나만 떼어 범용 SOTA로 읽기는 어렵다.

논문별 상세 분석

이 글은 세 연구의 차이를 빠르게 비교하는 허브다. Input·Process·Output, 학습 데이터, benchmark별 비교 조건과 재현 한계는 아래 독립 분석글에서 한 편씩 다룬다.

  • E2S-Pruner 논문 분석 — attention head와 layer의 충돌을 evidence fusion으로 다루는 전체 pruning 과정
  • FixAnything 논문 분석 — 3DGS·NeRF·mesh·sparse point를 한 video model로 보정하는 학습과 평가
  • GeoWAM 논문 분석 — 과거 multiview RGB에서 미래 point map과 ego trajectory를 만드는 두 단계 학습

1. E2S-Pruner — 불확실성을 남겨둔 채 visual token을 고른다

정식명: E2S-Pruner: Progressive Two-Stage Evidence Fusion for Visual Token Pruning in Vision-Language Models · arXiv v1 제출: 2026년 8월 24일 UTC

Attention 평균이 숨기는 두 가지 정보

일반적인 attention 기반 pruning은 여러 head나 layer의 score를 평균한다. 이 방식은 한 layer가 확신하고 다른 layer가 모르는 token과, 여러 layer가 정반대로 판단한 token을 비슷하게 취급할 수 있다. E2S-Pruner는 score 하나로 바로 줄이지 않고 important·unimportant·uncertain의 세 상태를 유지한다. Head와 layer가 얼마나 분명하고 서로 얼마나 충돌하는지를 token 선택에 남기는 셈이다.

마지막에는 spatial novelty constraint를 더한다. 24×24 patch grid를 4×4 spatial cell로 나누고, 각 occupied cell에서 score가 가장 높은 대표 token에 λ=0.1의 soft bonus를 준 뒤 전체 후보에서 다시 Top-K를 고른다. 서로 다른 image region을 덮도록 유도하지만 cell마다 token 하나를 반드시 남기는 hard quota는 아니다. 작은 글자나 세밀한 texture처럼 국소 patch 자체가 답인 과제에서는 극단적인 압축이 여전히 손실을 만든다.

32개 LLM layer에서 평균 64 token을 처리한 효율 측정에서 end-to-end latency는 dense 대비 51.5% 줄고 throughput은 2.09배가 됐다. 실제 LLaVA schedule은 576→20→8→0이며 마지막까지 64개를 유지하지 않는다. 같은 설정의 MMBench 성능은 dense의 88.7%다. Aggregate retention 90.6%와 MMBench retention 88.7%는 같은 숫자가 아니다. 전자는 GQA·ScienceQA·TextVQA·POPE·MME·MMBench 여섯 지표를 dense score로 정규화한 평균이다.

가장 분명한 약점은 TextVQA다. 평균 64-token budget에서 E2S-Pruner는 49.5로 LLaVA-PruMerge 54.0보다 낮다. 또 논문이 보고한 peak GPU memory는 dense baseline보다 20.8% 늘었다. Token을 줄이면 언제나 memory까지 줄어든다고 가정할 수 없는 이유다.

공개 상태: 논문은 공식 GitHub를 code link로 제시하지만 8월 26일 확인 당시 저장소는 비어 있다. 별도 학습 weight가 필요한 방법은 아니어도 pruning 구현과 정확한 evaluation configuration이 없어 즉시 재현하기는 어렵다.

2. FixAnything — 3D representation을 영상으로 펼쳐 고친다

정식명: FixAnything: 3D-Consistent Rendering Refinement via Video Generative Priors · arXiv v1 제출: 2026년 8월 24일 UTC · 발표: ECCV 2026

Representation과 무관한 이유

3DGS의 floater, NeRF의 foggy geometry, mesh의 texture distortion, point cloud의 hole은 생김새가 다르다. 그래도 camera motion과 대략적인 scene layout은 rendering video에 남는다. FixAnything은 representation 내부 parameter를 고치는 대신 이 공통 신호를 video-to-video translation의 control로 쓴다. 같은 model weight에 입력 rendering만 바꿔 네 표현을 처리할 수 있는 이유다.

Binary mask는 model이 보존해야 할 clean training view를 알려준다. SFT만 거치면 frame별로 그럴듯하지만 시점마다 움직이는 구조를 만들 수 있어, 연구진은 여러 rollout에서 COLMAP이 복원한 camera pose의 AUC@5°를 reward로 삼았다. AUC 차이가 0.2 이상인 pair를 Flow-DPO로 학습해 3D consistency를 LoRA에 반영한다.

Flow-DPO ablation에서는 SFT-only의 camera-pose AUC@5°가 61.12에서 68.32로 올랐고, PSNR은 17.51→17.65 dB, LPIPS는 0.296→0.289가 됐다. 화질 지표보다 pose recovery의 변화가 크다. 20 paired video로도 PSNR 16.70을 얻었다는 data-efficiency 결과가 있지만, 이는 model 전체를 20개 영상으로 학습했다는 뜻이 아니다. Wan2.1의 대규모 사전학습 prior 위에 conditioning LoRA를 맞춘 결과다.

공개 상태: Apache-2.0 추론 코드와 FixAnything LoRA가 공개됐다. Base model인 Wan2.1-I2V-14B-480P 파일은 약 60GB다. 공식 예제는 832×480, 61 frame을 사용하며 5 denoising step에서 단일 H100으로 약 31초를 보고한다. 실행 가능하다는 말과 가벼운 production component라는 말은 다르다.

3. GeoWAM — 미래의 픽셀보다 미래의 좌표를 예측한다

정식명: GeoWAM: Visual Geometry World Action Models for Autonomous Driving · arXiv v1 제출: 2026년 8월 24일 UTC · 현재 버전: v2, 8월 25일

두 단계 학습과 pseudo geometry target

첫 단계는 과거 multiview image로 미래 geometry를 맞히는 pretraining이다. 미래 frame 자체는 forecasting branch의 입력으로 주지 않고, 같은 geometry encoder가 만든 detached future feature와 dense point map을 target으로 쓴다. Feature cosine alignment, Euclidean·confidence-aware point regression, multi-scale surface-normal consistency가 supervision을 이룬다.

두 번째 단계에서는 미래 geometry token이 future ego/pose decoder를 조건화한다. Trajectory loss가 geometry forecaster를 임의로 바꾸지 않도록 stop-gradient를 둔다. 마지막 trajectory head는 anchor 후보나 mode classification 없이 하나의 경로를 직접 회귀한다. 논문이 말하는 “ground-truth occupancy annotation이 필요 없다”는 장점은 dense geometry supervision이 없다는 뜻이 아니다. Off-the-shelf geometry model이 만든 pseudo point-map target은 사용한다.

평균은 1~4초의 여덟 future frame을 묶은 값이다. Video world model은 먼저 미래 RGB를 생성하고 DVGT로 geometry를 다시 복원해 같은 metric으로 비교했다. 이 protocol에서는 GeoWAM이 Epona+DVGT보다 Abs Rel을 0.017 낮추고 threshold accuracy를 0.099 높였다. Geometry를 직접 예측한 VGGT-World와 비교해도 두 지표가 모두 좋다.

Navhard는 3DGS로 재구성한 장면에서 예측한 ego pose로 다음 관측을 다시 render해 오류를 누적시키는 pseudo-closed-loop 평가다. 실제 도로 주행 closed loop와 같지는 않다. 또 EponaV2 등 표에서 †로 표시된 방법은 RL 또는 PDMS-score supervision을 쓴다. GeoWAM은 그 supervision 없이 표 전체 최고를 기록했지만, 차이는 0.5점으로 작아 독립 재현과 여러 seed 평가가 필요하다.

공개 상태: 논문과 프로젝트 페이지는 공개됐지만 8월 26일 확인 당시 code와 checkpoint link는 없다. 논문은 CC BY 4.0이며 프로젝트 웹사이트의 CC BY-SA 4.0은 사이트 template에 대한 라이선스다. 향후 software와 model의 사용 조건은 별도로 확인해야 한다.

오늘의 우선순위

  • 직접 실행하려면 FixAnything: 세 편 가운데 실제 inference code와 LoRA가 공개됐다. Base model 용량과 H100 기준 속도는 먼저 계산해야 한다.
  • VLM inference 비용을 줄이려면 E2S-Pruner: 학습 없이 붙이는 구조가 매력적이다. 공식 구현 공개 전에는 128~192 token budget부터 자체 baseline을 만드는 편이 현실적이다.
  • Physical AI 연구 방향을 본다면 GeoWAM: Pixel generation보다 action과 같은 metric space의 geometry forecasting이 planning에 유리하다는 근거를 제시했다. 아직 재현 가능한 공개물은 없다.

세 연구는 모두 더 큰 backbone을 제안하지 않았다. E2S-Pruner는 추론 중 남길 증거를 가려낸다. FixAnything은 서로 다른 3D 표현을 공통 video interface로 바꾸고, GeoWAM은 world model의 예측 공간을 action과 가까운 3D 좌표계로 옮긴다. 제품 적용을 검토한다면 headline score보다 입력 계약과 공개 상태를 먼저 보는 편이 빠르다.
